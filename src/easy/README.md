# Easy Level - Базовые Code Smells

Эта категория содержит примеры простых проблем в коде, которые легко выявить и исправить. Подходит для проверки базовых знаний о чистом коде.

## Список файлов и проблем

### 1. `addError.ts` - Мутация входных параметров

**Проблема**: Функция мутирует переданный массив, что может привести к неожиданным побочным эффектам.

```typescript
const addError = (errors: TMutableList<TWarning>) => {
  errors.push(Warning(WarningType.LEGACY_CODE_DEPENDENCY)); // Мутация входного параметра
};
```

**Что нужно исправить**:

- Возвращать новый массив вместо мутации входного
- Использовать immutable подход

---

### 2. `calculate.ts` - Плохое именование функции

**Проблема**: Имя функции не описывает, что она делает.

```typescript
const calculate = (number: number) => {
  return number * number; // Возводит в квадрат, но имя не отражает это
};
```

**Что нужно исправить**:

- Переименовать в `square` или `calculateSquare`
- Добавить JSDoc комментарий

---

### 3. `calculate2.ts` - Отсутствие типизации

**Проблема**: JavaScript код без типов в TypeScript проекте.

```javascript
function calculate(a, b) {
  // Нет типов
  return a + b;
}
```

**Что нужно исправить**:

- Добавить типы для параметров и возвращаемого значения
- Переименовать функцию в соответствии с её назначением

---

### 4. `calculateArea2.ts` - Магические числа

**Проблема**: Использование магического числа вместо константы.

```typescript
function calculateArea2(radius: number): number {
  return 3.14 * radius * radius; // Магическое число 3.14
}
```

**Что нужно исправить**:

- Использовать `Math.PI` вместо 3.14
- Добавить валидацию входных параметров

---

### 5. `Calculator.ts` - Отсутствие обработки ошибок

**Проблема**: Деление на ноль не обрабатывается.

```typescript
public divide(a: number, b: number): number {
  return a / b; // Деление на ноль не обрабатывается
}
```

**Что нужно исправить**:

- Добавить проверку на ноль в делителе
- Выбросить исключение или вернуть специальное значение

---

### 6. `Calculator2.ts` - Смешанные стили кода

**Проблема**: В одном файле функция и класс, отсутствие типизации.

```javascript
function add(a, b) {
  // Функция без типов
  return a + b;
}

class Calculator2 {
  multiply(a, b) {
    // Метод без типов
    return a * b;
  }
}
```

**Что нужно исправить**:

- Добавить типизацию
- Разделить на отдельные модули или объединить в один класс

---

### 7. `Car.ts` - Простая проблема с типизацией

**Проблема**: Статический метод использует `this` некорректно.

```typescript
public static isColorAvailable(color: string): boolean {
  return this.COLORS.includes(color); // this в статическом методе
}
```

**Что нужно исправить**:

- Использовать `Car.COLORS` вместо `this.COLORS`

---

### 8. `DaoCacheConfigProperties.ts` - Плохие комментарии

**Проблема**: Комментарии дублируют код.

```typescript
class DaoCacheConfigProperties {
  alive: number; // alive cache time in days - избыточный комментарий
  elements: number; // maximum elements in cache - избыточный комментарий
}
```

**Что нужно исправить**:

- Использовать осмысленные имена свойств
- Убрать избыточные комментарии или заменить на JSDoc

---

### 9. `errors.ts` - Непоследовательность в именовании

**Проблема**: Разные стили именования констант.

```typescript
const hasNotFoundStatus = (response: Response) => {
  return response.status === HttpStatusCode.NOT_FOUND_404;
};

const hasServiceUnavailableStatus = (response: Response) => {
  return response.status === 503; // Магическое число
};
```

**Что нужно исправить**:

- Использовать константы вместо магических чисел
- Единообразный стиль именования

---

### 10. `formatPhoneNumber.ts` - Отсутствие типизации и магические числа

**Проблема**: JavaScript код с магическими числами.

```javascript
function formatPhoneNumber(number) {
  // Нет типов
  return `(${number.slice(0, 3)}) ${number.slice(3, 6)}-${number.slice(6)}`; // Магические числа
}
```

**Что нужно исправить**:

- Добавить типизацию
- Вынести магические числа в константы
- Добавить валидацию

---

### 11. `isEmpty.ts` - Отрицательные условия

**Проблема**: Использование отрицательного условия.

```typescript
if (!isEmpty(list)) {
  // Отрицательное условие
  // код, если список не пуст
}
```

**Что нужно исправить**:

- Создать функцию `isNotEmpty` для более читаемого кода
- Или переписать логику с позитивным условием

---

### 12. `match.ts` - Отсутствие проверки на null

**Проблема**: Использование результата `match` без проверки.

```typescript
const match = rawHeaderLine.match(headerPattern);
headers.set(match[1].toLowerCase(), match[2]); // match может быть null
```

**Что нужно исправить**:

- Добавить проверку на null
- Обработать случай, когда паттерн не найден

---

---

### 13. `asyncProblems.ts` - Неправильная обработка промисов

**Проблема**: Отсутствие обработки ошибок, смешивание async/await и .then().

```typescript
async function fetchUserData(userId: string) {
  const user = await fetch(`/api/users/${userId}`); // Нет обработки ошибок
  const userData = await user.json();

  const posts = await fetch(`/api/users/${userId}/posts`); // Последовательные запросы
  const postsData = await posts.json();

  return { user: userData, posts: postsData };
}
```

**Что нужно исправить**:

- Добавить try/catch блоки
- Использовать Promise.all для параллельных запросов
- Проверять статус ответа

---

### 14. `dataClass.ts` - Data Class антипаттерн

**Проблема**: Класс содержит только геттеры/сеттеры без бизнес-логики.

```typescript
class PersonData {
  getFirstName(): string {
    return this.firstName;
  }
  setFirstName(firstName: string): void {
    this.firstName = firstName;
  }
  // ... только геттеры и сеттеры
}
```

**Что нужно исправить**:

- Добавить бизнес-логику в класс
- Использовать readonly свойства где возможно
- Переместить связанную логику из других классов

---

## Общие принципы для исправления

1. **Используйте осмысленные имена** для переменных, функций и классов
2. **Добавляйте типизацию** во всех местах
3. **Избегайте магических чисел** - выносите в константы
4. **Обрабатывайте ошибки** и граничные случаи
5. **Не мутируйте входные параметры** без необходимости
6. **Следуйте принципам чистого кода** и единообразию стиля
