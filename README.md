# Candidates for Refactoring - Тестовые задания для Senior Frontend разработчиков

Этот репозиторий содержит коллекцию примеров кода с различными code smells, антипаттернами и архитектурными проблемами. Предназначен для оценки навыков рефакторинга кандидатов на позицию Frontend разработчика.

## Структура проекта

Все примеры кода организованы по уровню сложности:

### 🟢 Easy Level (`src/easy/`)

**Базовые code smells** - простые проблемы, которые легко выявить и исправить:

- Плохое именование функций и переменных
- Отсутствие типизации в TypeScript проекте
- Магические числа и строки
- Отсутствие обработки ошибок
- Мутация входных параметров
- Отрицательные условия
- Мертвый код и неиспользуемые методы

**Количество примеров**: 14 файлов  
**Примеры файлов**: `calculate.ts`, `asyncProblems.ts`, `dataClass.ts`

### 🟡 Medium Level (`src/medium/`)

**Нарушения принципов SOLID** и архитектурные проблемы средней сложности:

- Нарушение Law of Demeter (транзитивные обращения)
- Нарушения принципов SOLID (SRP, OCP, LSP, ISP, DIP)
- Функциональная зависть (Feature Envy)
- Использование switch вместо полиморфизма
- Слишком много аргументов в методах
- Смешанные уровни абстракции
- Неправильное использование наследования

**Количество примеров**: 22 файла  
**Примеры файлов**: `ABC.ts`, `primitiveObsession.ts`, `reactProblems.tsx`, `shotgunSurgery.ts`

### 🔴 Hard Level (`src/hard/`)

**Сложные архитектурные антипаттерны** требующие глубокого рефакторинга:

- Нарушение Single Responsibility Principle в сложных сценариях
- Скрытые временные привязки
- Сложная условная логика
- Дублирование кода на архитектурном уровне
- Неправильное управление состоянием
- Проблемы с API дизайном
- Необходимость применения паттернов проектирования

**Количество примеров**: 14 файлов  
**Примеры файлов**: `godObject.ts`, `circularDependency.ts`, `debuggingChallenge.ts`
**Специальные тесты**: `DEBUGGING_CHALLENGE.md` - комплексный тест на чтение кода и дебаггинг

## Задание для кандидатов

### Что нужно сделать

1. **Выберите уровень сложности** соответствующий вашему опыту
2. **Сделайте рефакторинг** выбранных файлов (минимум 50% от общего количества)
3. **Напишите комментарии** к каждому измененному модулю:
   - Что было плохо и почему
   - Что стало лучше и почему
4. **Выявите и опишите** все найденные code smells и антипаттерны

### Критерии оценки

- ✅ Выявление проблем в коде
- ✅ Качество рефакторинга
- ✅ Понимание принципов чистого кода
- ✅ Знание паттернов проектирования
- ✅ Архитектурное мышление

## Специальные тесты

### 🔍 Debugging Challenge (`src/hard/DEBUGGING_CHALLENGE.md`)

**Комплексный тест на чтение кода и дебаггинг** - проверяет способность:

- Анализировать сложный код без запуска
- Строить ментальные модели выполнения программы
- Отслеживать поток данных и стек вызовов
- Понимать асинхронные операции и промисы
- Выявлять race conditions и утечки памяти

**Время выполнения**: 80 минут  
**Формат**: Статический анализ кода + ответы на вопросы  
**Подходит для**: Senior+ разработчиков

**Включает:**

- Анализ архитектуры системы
- Трассировка потока выполнения
- Выявление критических багов
- Предложения по оптимизации
- Планирование тестирования

## Оформление результата

1. **Сделать fork** этого репозитория
2. **Создать новую ветку** для работы над тестовым заданием `test-assignment`
3. **Внести изменения** в выбранные файлы
4. **Создать Pull Request** с изменениями в вашем fork:
   - Перейдите на страницу вашего fork
   - Нажмите вкладку "Compare & pull request"
   - **Убедитесь**, что база (base) указана на **ВАШ** fork репозиторий
   - Сравнение (compare) должно быть на вашу ветку `test-assignment`
   - Добавьте подробное описание изменений
   - Нажмите "Create pull request"
5. **Отправить ссылку** на Pull Request

## Как использовать (для интервьюеров)

### Рекомендуемый процесс

1. Предложите кандидату выбрать 2-3 файла из соответствующего уровня
2. Попросите выявить проблемы и объяснить их
3. Дайте время на рефакторинг (указано для каждого уровня)
4. Обсудите предложенные решения
5. Используйте README файлы в папках как reference для оценки

### Уровни сложности по опыту

- **Junior → Middle**: Easy Level
- **Middle → Senior**: Medium Level
- **Senior → Lead**: Hard Level

## Примечания

- Примеры кода **абстрактны** и призваны продемонстрировать конкретные проблемы
- **Дописывать** недостающие методы, функции и типы **не требуется**
- Фокус на **качестве рефакторинга**, а не на полноте реализации
- Важно **объяснить свои решения** и **обосновать изменения**
